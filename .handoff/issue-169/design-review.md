# #169 independent cross-review

## Decision

Choose **A's occurrence-coupled provenance and same-leaf policy**, simplified to the minimum fields needed to classify a collision and identify sources. Do not adopt B's reference-keyed/parallel trace or its customization-and-name-only test. Both candidates preserve current last-wins, not the original triage checklist's run-both behavior; the later maintainer comment explicitly selects this minimum compatible repair. Classification is a documented convention, not proof of intent. No algorithm can tell whether a whole-set-then-targeted reference was intentionally an override without an explicit marker.

This review is against clean `messharp` HEAD `56a7054c47b90cd51e0a3c1b52900a544752f234`, the issue comments, designs A/B, and `.audit/169-red.log`. The red log is a prior run, not an independently rerun test: it shows one CLI reproduction failing because stderr is empty. The repo at that HEAD does not contain that red test. Conclusions about the proposed implementations are static analysis, not measurements of code that does not yet exist.

## Concrete counterexamples and resolver facts

1. **B silently loses an unrelated definition.** Let `a.xml` declare `<rule name="CyclomaticComplexity" class="PHPMD\Rule\CyclomaticComplexity" .../>`; a composite has `<rule ref="a.xml"/>` followed by `<rule ref="codesize/CyclomaticComplexity" message="custom"/>`. The two candidates have the same effective name, but different definition declarations. B's whole-set/target-name/customization predicate classifies this as an override and suppresses the warning. `ProcessClassRule` sets names from `def.Name`, not the ref (`XmlRulesetParser.cs:69–78`), and dedupe is by that name, not class or leaf. A's same-leaf condition correctly warns. Same issue occurs if a named probe matches multiple same-name leaves within a composite: each discard must be checked against the final winner's actual leaf, not only the requested name.
2. **B warns on a legitimate uncustomized explicit selection.** `<rule ref="csharp"/><rule ref="naming/LongVariable"/>` in one composite selects the later naming default, replacing csharp's maximum=35 with the leaf default. An explicit selection can reset inherited configuration without specifying fields; requiring a customization is not justified by the resolver or issue. A treats it as an override when both resolve to the same leaf. This exact no-customization quietness is a proposed policy, not an existing test guarantee. Conversely A's allowance can suppress an independent targeted import indistinguishable from a reset; document that unavoidable ambiguity.
3. **The cross-root exception must not be generalized.** `set1.xml,set2.xml`, each with a targeted customized ref to the same `codesize/CyclomaticComplexity` leaf, is the issue reproduction: final set wins *and warning is required*. Sharing the leaf is insufficient. But `csharp,custom.xml`, with a direct named LongVariable override, must preserve the existing CLI test's empty stderr and max=50 (`CliTests.cs:388–407`). A's bounded direct-builtin-root convention handles both. It can also suppress genuinely independent definitions in that narrow shape; that is a deliberate compatibility tradeoff, not certainty. A custom XML wrapping csharp as an earlier root does not qualify and warns; state that limitation.
4. **First divergence matters.** In one outer XML, two sibling whole-set refs both ultimately import the same leaf, with distinct messages: warn even if the later child internally used a named ref. Looking only at the leaf or searching for any later named step would suppress a real collision. For a nested composite whose own sibling declarations are whole-set then named, compare at that nested shared expansion scope; do not confuse two separate expansions of the same source or identify scope just by path text/source and declaration ordinal.
5. **Original versus synthetic ref matters.** `ResolveNestedRule` synthesizes `child.Ref = $"{sr.Ref}/{ruleName}"` while probing (`RuleRefResolver.cs:86–105`). That synthetic named target is not an author-written targeted override. Likewise `MergeChildRef` combines parent/child settings and excludes (`XmlRulesetParser.cs:98–114`); inspecting the merged XML alone can falsely attribute an override to the wrong boundary. Carry original declarations and the requested probe target separately. `SplitRef` first checks an entire existing file/builtin, then a resolvable prefix, then the bare builtin index (`LoaderFilters.cs:54–68`); classify using actual resolution rather than presence of `/` or a string suffix.
6. **Do not invent rollback semantics.** `AddRef` appends while iterating and only throws no-match when `matched` is false (lines 48–56); `ResolveNestedRule` catches *any* `InvalidOperationException` from a recursive probe (lines 97–104), not just a typed no-match. Rule building/population can itself throw. B's proposed rollback of actual appended rules could alter current behavior on a partially appended failed probe. Preserve current resolver behavior in this narrow repair: couple metadata atomically to every accepted append, including any append the existing code retains after a caught exception; only a separately justified bug fix should change that behavior. If a load ultimately throws, do not issue collision notices for the incomplete load. Existing other warnings are already immediate.

## Metadata safety and simplest viable representation

Use one per-load owned candidate/occurrence `(IRule, origin)` at append time and dedupe those candidates directly; materialize the public `RuleSet.Rules` after dedupe. A full public provenance model or rich graph is unnecessary. A persistent linked immutable path can share ancestor frames; each frame records occurrence-specific owner scope, declaration ordinal and original ref kind/target. Include root ordinal/display and leaf source identity + declaration ordinal. Leaf identity must identify the resource actually read (built-in canonical key or normalized file path under an explicitly defined comparer) plus XML rule ordinal; do not silently change `ReadRuleset` lookup precedence or `visited` cycle semantics. Conservative failure to prove identity => warn. Display the original input and enough path/ordinals to distinguish repeated roots and same-named files; sanitize CR/LF in all untrusted diagnostic components, including rule names.

B's reference dictionary is unsafe as an invariant: duplicate appends of one object reference alias, even if today's `RuleFactory.Create` normally creates instances. A side-by-side list has a positional alignment invariant across every append, filtering, clearing, and caught failure; A's candidate makes metadata inseparable and gives one dedupe source of truth. If a smaller trace is used instead, enforce reference uniqueness and count/position synchronization mechanically and test them; do not assume either. Avoid reusing the existing loader-owned resolver to hold session fields: pass a local per-call context or construct a per-call resolver, and do not introduce static state. This does not promise thread safety for concurrent mutation of the existing mutable Loader settings/callbacks.

`AppendIfNotNull` only accepts `BaseRule` after priority checks (`Loader.cs:101–106`), so atomically append candidate and metadata there. False positives from source aliases are preferable to silencing an unexplained collision; do not infer leaf identity from display set name, classname, message, rule object value, or path spelling alone. A's canonicalization must not equate distinct resources merely because their displays match or case-fold file paths on a case-sensitive filesystem.

## Implementable invariants and delivery

- Preserve expansion, merges, excludes, exceptions, priority selection and output ordering. Reverse traverse sets and rules with `StringComparer.Ordinal`; hold the final winner per name. Every earlier duplicate is compared against that final winner and dropped exactly as now. Keep empty sets and survivor order; priority filtering is before dedupe, CLI `--only`/disable after it. Warnings do not change winner, analysis, report bytes, or exit status.
- Suppress a discard only if the two resolved leaves are the same *and* either (a) at their first divergent declaration in a shared expansion occurrence the earlier branch is whole-set and the later branch is an actual author-written named selection of that leaf, or (b) the earlier comma root is a directly selected built-in whole set and the later root has a direct top-level named selection resolving to that leaf. In both cases the winner itself must enter through the qualifying named branch. Otherwise emit one notice per discarded occurrence, naming the effective rule, discarded and actual winning source/path. Root IDs must distinguish repeated occurrences, even when the original strings match. Do not claim intent as fact.
- Existing library clients setting only `Warn` must receive collisions. An additive `CollisionWarn` callback is defensible to preserve legacy CLI verbosity: invoke `(CollisionWarn ?? Warn)` exactly once per collision; document that setting the specialized sink overrides `Warn` for this category. CLI configures collision sink unconditionally to stderr and existing `Warn` only under `--verbose`; no double emission, no stdout/report-file contamination. Null callbacks remain allowed. Callback exceptions follow ordinary current callback exception behavior; don't swallow them silently. Warnings are generated only once expansion succeeds, before later rule-name filtering, and in deterministic reverse-discard order.
- Verify three-way A/B/C => two notices both naming C; reversal; same-leaf independent roots; same/different-leaf siblings; nested same scope vs distinct expansion instances; bare and qualified #115; csharp cross-root max=50 with empty stderr; uncustomized reset; direct classes; repeated roots; same ruleset display name/different files; priority/exclude/unknown rule; synthetic nested probes; repeated calls; failed loads/caught probes. Capture the actual rule configuration and warning sources, not just count.
- Test callbacks with Warn only / collision only / both / neither, with and without verbose; capture CLI stderr separately from JSON, XML and report-file content, parse each, assert winner and unchanged 0/1/2 exit behavior. Run the actual red reproduction and existing focused/full tests and repository's prescribed Docker/self-analysis gates before declaring success.
